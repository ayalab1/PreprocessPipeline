# flex-G5 ver2: XML-ordered wiring

- Date: 2026-10-06

## Behavior

The existing `flex-G5` uses a fixed device-channel wiring table. The PFC2 XML
uses different wiring, so assigning each of its 32-channel groups to that
geometry produced alternating shapes and placed channels 15/16 at the top.

`flex-G5 ver2` is a separate GUI geometry choice. It assigns XML channels in
their listed order to the original flex-G5 contact positions. Each complete
32-channel shank is traversed from top to bottom, with left before right for
contacts at the same height. The first channel is the top anchor; the next is
the center contact 800 um below it, followed by a left/right pair 15 um lower.

The original geometry is reused: lateral spacing 21.5 um, vertical row spacing
15 um, top-anchor separation 800 um, paired-shank spacing 80 um, and 64-channel
block spacing 1000 um. Assignment centers still use `x offset`. Skipped and
rejected channels retain their positions and only change the connected mask.
The original `flex-G5` keeps its device-ID mapping.

## XML and GUI use

- Select `flex-G5 ver2` in each desired probe-assignment row. XML descriptions
  containing that name also select it automatically; saved `flex_g5_v2` and
  `flex-g5-ver-2` aliases normalize to the same GUI choice.
- A 32-channel XML group describes one shank. Two consecutive 32-channel groups
  within an assignment form a paired 64-channel block, as for the original
  geometry. Larger groups must list complete 32-channel shanks consecutively.
- Group sizes that are not multiples of 32 are rejected. Keep bad channels in
  their physical positions in the XML and mark them skipped instead of deleting
  them from the sequence.
- XML order is authoritative for ver2. It must be checked against the physical
  wiring; ver2 does not infer or repair channel order from the reference image.
  For the current PFC2 XML, group 1 starts `62, 33, 63, 31`, so ver2 places 62
  at the top, 33 at the next center site, then 63/31 at the next left/right pair.
  The user confirmed that 62 is the correct top contact. This does not validate
  the remaining order against the drawing, whose second center site reads 63.
- No source XML, saved configuration or existing chanMap was rewritten.
